# Solana gateway — protocol v7.2

Program `spawn_gateway`, id `3mypQvfiLtRHQhWStYyQ6cUu6YC4hqUFBXcNNme3H95g`,
chain label **1**, LayerZero eid **30168** (devnet 40168). It speaks to the
Base hub the way an EVM `SpawnGateway` does. The hub is immutable once
deployed: everything below is built around what it sends.

**Status (2026-11-14): brought to the v7.2 wire and proven locally against
the real mainnet LayerZero programs and state, and against Circle's real
CCTP V2 programs. Never deployed anywhere — not even devnet. No packet has
ever crossed to or from it. Not audited. The v7.2 hub is itself not
deployed yet; the hub addresses that appear below (pad `0xC2f3…3811`,
adapter `0xc030…Ce34`, vault `0xada6…04C2`) belong to the retired v7.0
deployment and stand for "the pad", "the adapter", "the Base vault".**

What v7.2 changed here (the rest of this file is updated in place):

- **the wire** — BUY and SELL carry a minimum (required on this chain: one
  unit says "anything"); the envelope's fourth word is the reply budget the
  message must arrive with (the hub adapter refuses less); ops 6 (OPEN) and
  7 (MOVE);
- **`open_token`** — asks the hub for a token this chain was left out of;
  the opener also leaves the replica's rent at its two addresses, so the
  SYNC that answers costs nobody anything;
- **`move_claim`** — a claim leaves for another chain at that chain's own
  price (`set_move_legs`, the operator's); never paused;
- **a PAYOUT for any 32-byte recipient** — a claim moved HERE names a
  recipient typed on another chain: it is paid, or booked in a user account
  opened on the spot (§2 row 13);
- **CCTP out** — `set_cctp_peer` (admin, once per label) and `rebalance`
  (operator) level the vault with the EVM vaults;
- **gaps closed** — the store is born paused; the executor's lookup table
  can be named after `init_store` (`set_receive_table`) and is frozen once
  full; the wiring pins both LayerZero libraries.

## 1. Where Solana differs from an EVM spoke, and why

Three facts of the platform drive every difference:

- **No try/catch.** A failed CPI takes the whole transaction down, and with
  it the hub message being delivered. So `lz_receive` checks first everything
  that could make a token CPI fail (vault balance, the token accounts being
  initialised and not frozen) and never attempts a transfer that can fail.
- **Accounts cost rent, and somebody must pay it.** The hub's messages reach
  Solana with a native value of zero (§2), and LayerZero's executor refuses to
  spend its own SOL. So `lz_receive` may not create an account at its caller's
  expense: what a hub message itself calls for (a replica, the account of a
  recipient who never came here) is paid by the program's tank — or was
  prepaid by whoever asked (`open_token`).
- **SPL tokens have no transfer hook** (classic Token program; USDC is one).
  Nothing can observe a wallet-to-wallet transfer.

What follows from them:

| EVM spoke | Solana | Why |
|---|---|---|
| `OmniUSD` — an ERC-20 oUSD wrapping the vault's USDC | **No SPL oUSD.** A USDC vault (token account PDA `["Vault"]`, authority = the store) plus a per-user `usd_claim` in the user's account | oUSD exists on EVM so that a payout the vault cannot make becomes a transferable balance. A second mint here would need a token account per user (rent nobody can pay at delivery time) and adds nothing: nothing on Solana consumes oUSD. A claim is a number in an account the user already owns. |
| A payout that cannot be made mints oUSD | It becomes a **claim** (`redeem_claim` when the vault has USDC again, or `move_claim` to a chain that can pay it). Triggers: vault short, vault frozen, recipient's USDC account missing, frozen or not theirs — **for any 32-byte recipient** (v7.2): one who never came here gets a user account opened on the spot, out of the tank | Same rule, without the token. An EVM spoke reverts on a recipient that is not an address (the hub filters them); here every 32 bytes are a possible key, so nothing may revert |
| `moveClaim` burns oUSD, which `wrap` can mint from USDC | `move_claim` burns the caller's **claim** only. No `wrap`: USDC in a wallet cannot leave this way | The USDT vault's rule (`OmniUSDLocal`), for the same reason: wrap + move is a free exchange through the vaults |
| `openToken` prepays the SYNC | `open_token` prepays the SYNC **and leaves the replica's rent** (0.0027 SOL) at the replica's and the mint's addresses | The SYNC arrives with no lamports; this way it needs none, whoever executes it |
| `buyTokenUsdc` / `buyTokenUsdcMin`, `sellToken` / `sellTokenMin` | One `buy_token`, one `sell_token`, **a minimum required** (`ZeroMinimum`); one unit (0.000001) says "anything" | Every trade from here is cross-chain: it executes minutes after it is public and anyone may deliver it. There is no synchronous path where an unprotected trade is safe, so there is no unprotected entry point |
| The gateway deploys the replica and mints to any address | `SYNC` creates the replica entry + SPL mint **out of the program's tank** (`["GasTank"]`); a `DELIVER` mints into the token account the buyer created when they bought | Rent. Users pay their own accounts when they send; only `SYNC` has nobody to charge |
| A `DELIVER` that beats its `SYNC` is parked in the gateway | Parked **in the recipient's user account**, to the wei (max 4 tokens at once), claimed with `claim_parked` | Same rule; the user account is the one account that always exists (or is opened on the spot) |
| `FeeDistributor`: shares follow wallet balances through the transfer hook | **Stake to earn.** Replicas staked in the token's escrow earn the chain's holder-fee slice pro rata (`stake` / `unstake` / `claim_rewards`). Unstaked balances earn nothing | No hook, so wallet balances cannot be tracked. Unstaking is always open, even when paused |
| One legacy transaction per action | Sends need a **v0 transaction with an address lookup table** | A buy touches 40 accounts: 1509 bytes legacy, 553 bytes with the store's table |
| `quoteBuy()` etc. are views | `quote_send` is a simulated instruction; the send itself takes a fee **ceiling** (`max_native_fee`, 0 = none) and pays the actual fee | The ULN charges the real fee and only checks it against the ceiling. An on-chain quote before each send doubled the compute and ran out of heap with a mainnet pathway's 5 workers |

Every user-facing send (`spawn_token`, `buy_token`, `sell_token`,
`claim_fees`) creates, at the user's expense, the accounts the reply will
need: their user account, their USDC account, and for a buy their token
account. That is what lets every reply to a TRADE settle with zero lamports.
Two messages are not replies to someone who prepared accounts here: a SYNC
(nobody on Solana asked for it — unless it answers an `open_token`, whose
caller prepaid its rent) and the PAYOUT of a claim moved from another chain
to a recipient of the mover's choosing. Those two draw on the tank.

One wrinkle that cannot be designed away: **a dev buy on a spawn from Solana
always takes a second transaction.** The creator cannot hold a token account
for a mint that does not exist yet, so the dev buy's `DELIVER` is parked and
the creator runs `claim_parked`.

Roles mirror `Roles.sol`: **admin** (two-step transfer; also the LayerZero
delegate, moved to the new admin on `accept_admin`) wires peers, names
operator and guardian, recovers the tank, names the executor's lookup table
and the CCTP peers; **operator** sets prices (fee config, open legs, move
legs per destination) and the deposit cap, rebalances the vault toward a
named peer, and unpauses; **guardian** pauses. A pause blocks buys, spawns
and opens, never sells, claims, pulls, moves, redemptions, unstaking or
inbound messages. **A store is born paused.**

## 2. Where the immutable hub constrains Solana

| # | Constraint (what the hub does, forever) | Status | How |
|---|---|---|---|
| 1 | **Options format.** The hub adapter builds `abi.encodePacked(uint16 3, uint8 1, uint16 17, uint8 1, uint128 gas)` — a type-3, single `lzReceive` option | **Solved** | It is exactly what LayerZero's Solana executor reads. Base's executor quotes it for eid 30168 today (0.00078 ETH for 300k on the default verifiers). The program builds the same bytes for its own sends; cross-checked against ethers' `solidityPacked` (`options` vectors) |
| 2 | **`value` is always 0 toward Solana.** The pad passes `returnLegs = 0` on every message it originates, so the 33-byte form is never used: a hub message can never carry lamports (and the envelope's fourth word is 0) | **Bounded — by the tank** (§9: the one thing worth asking of the hub) | No reply to a trade needs lamports (§1). The two messages that may have to create an account — a `SYNC`, a moved claim's `PAYOUT` for a recipient with no account here — take the rent from the tank. Proven by running LayerZero's real executor program with `value = 0`: it delivers all of them, and with a DRY tank refuses (`InsufficientBalance`) exactly those two, leaving the packet intact — executable again once the tank is refilled, once anyone opens the missing account, or by anyone who pays the rent |
| 3 | **`gas` means compute units** on Solana: `gasLimit[1]`, or since v7.2 one number per kind of message (`gasForOp[1][op]`), operator-set | **Solved — needs the number set** | Measured through the real executor and the real endpoint `clear`: at most ~171k CU (§5). Set `gasLimit[1] = 400_000` and leave `gasForOp` unset. Price is flat: 100k → 400k CU costs +0.000013 ETH per message |
| 4 | **A token's `SYNC` reaches a chain at launch, or when someone asks.** v7.2: the fan-out skips a chain above its `syncCap`; `resync` (anyone, paid on the hub) and `OP_OPEN` (from the chain itself) send it later | **Solved** | A `SYNC` is never lost: with a dry tank it waits, executable by the executor once the tank is refilled or by anyone willing to pay 0.0027 SOL. A second `SYNC` is ignored. A token Solana never got — skipped, failed, or older than the leg — is opened from here: `open_token` prepays the hub's SYNC and its rent |
| 5 | **Every launch on every chain sends a `SYNC` to Solana, synchronously** (`_spawn` loops `messenger.send`). If that send reverts, the launch reverts | **Blocking until the hub-side config is in the same batch** | LayerZero's default executor config for Base → Solana admits **200-byte** messages (read from Base mainnet; `endpoint.quote` reverts `LZ_MessageLib_InvalidMessageSize(384, 200)`). Hub messages are 288–480 bytes. The adapter's executor config for eid 30168 must be raised to 10,000 **before** `pad.setGateway(1, …)` executes, in the same atomic timelock batch (§7) — otherwise every launch on Base, Optimism and Arbitrum reverts until a second 48h operation fixes it |
| 6 | **Message size vs Solana's 1232-byte transaction.** The largest hub message (a `SYNC` with a 64-byte name and 16-byte symbol) is 512 bytes (v7.2: each message is one word longer) | **Solved locally, unproven live** | The executor transaction is 803–1038 bytes for all four messages with a lookup table of the static accounts (measured). Whether LayerZero's off-chain executor builds it that way is only provable on a live cluster |
| 7 | **Supply accounting (SPEC F-4).** The hub counts label 1's supply in 18 decimals; SPL mints have 6 | **Bounded: under 1e12 wei (one millionth of a token) per token, ever** | Each replica carries the unminted remainder (`dust_carry`) into the next delivery: Σ minted × 1e12 + carry = Σ delivered, exactly. Sells burn whole SPL units and send `units × 1e12`: always an exact multiple, so the hub is never asked for dust it does not think label 1 has. Parked deliveries are kept to the wei |
| 8 | **Dollar amounts are 18-decimal** on the wire; USDC has 6 | **Bounded: under 0.000001 USDC per message** | Payouts round down; the remainder stays in the vault and is counted (`store.usd_dust_e18`). Deposits are exact (`usdc × 1e12`) |
| 9 | **Holder fees are split by chain supply**, staked or not, and reach a chain only when someone there pulls them | **Bounded — a disclosed difference** | `pull_fees` (op 5) brings the slice; stakers share it. If fewer than 1,000 tokens are staked the slice waits in `pending_fees` and goes to the first stakers to reach that floor. Holders who do not stake earn nothing on Solana |
| 10 | **Addressing.** Token ids, actors and gateways are `bytes32` on the wire; the envelope is `abi.encode(bytes32 srcSender, bytes32 dstAddr, bytes payload, uint256 value)` (v7.2) | **Solved** | Solana keys ride as they are. The program accepts a message only from the hub eid, from the LayerZero peer (the hub adapter), with `srcSender` = the pad and `dstAddr` = this store. A three-field (pre-v7.2) envelope is refused, not half-read |
| 11 | **Replies are prepaid in the hub's currency, and the hub adapter insists on it (v7.2).** The user's send carries `return_unit × legs` of Base ETH into the hub adapter's tank; the same number rides the envelope, and a delivery that brings less is refused | **Solved, at a price — and under a cap that is LayerZero's** | Solana's executor prices it: a 0.0002 ETH reply budget costs 0.0058 SOL today. A reply to Solana costs the hub ≈ 0.00028 ETH on our verifier set, so `return_unit` here should be ≈ 0.00035 ETH → **a buy from Solana costs ≈ 0.0115 SOL** in messaging. LayerZero's Solana executor admits at most **0.05 ETH of value per message toward Base** (its config, mainnet snapshot): `return_unit × legs` above it and the send is refused whole (`NativeAmountExceedsCap`, tested at 250 / 251 legs of 0.0002 ETH). `set_move_legs` allows 4,096 legs; the operator must price a dear destination under the cap |
| 12 | **`pad.setGateway` is permanent.** There is no way to remove a chain | **A decision, not a defect** | After the batch executes, every launch whose fan-out reaches Solana pays one more `SYNC` (≈ 0.00028 ETH, prepaid by the launcher) and the Solana tank pays 0.0027 SOL of rent. `syncCap[1]` (operator, reversible) takes Solana out of the fan-out: tokens are then opened from here, at the opener's expense |
| 13 | **A recipient someone chose (v7.2).** `OP_MOVE` makes the hub forward a PAYOUT to ANY non-zero 32-byte `to` on a non-EVM gateway | **Solved; one bound — the tank** | No recipient can make a PAYOUT fail or its account list unresolvable (§3). USDC if the vault and the recipient's own USDC account allow it, else a claim in the recipient's user account — opened on the spot for one who never came here: 0.0019 SOL from the tank. Dry tank: that PAYOUT waits (row 2). A recipient nobody holds the key of (an EVM address pasted for a move to Solana, a program) gets a claim nobody can redeem — the sender's mistake, as with any transfer; the hub does not filter it (§9) |
| 14 | **A claim moved OUT is paid where the hub can hand it on, else comes home.** `OP_MOVE` is forwarded only under `requestCap[dst][12]`; the way home is a reply | **Solved** | `move_claim` burns the claim first; if it comes home the PAYOUT names `from`, whose user account exists (it held the claim). The move prepays `max(move legs of that destination, trade legs)` |
| 15 | **A trade under its minimum is refused whole (v7.2).** A buy's dollars come home in a `DELIVER`'s refund; a sold bag is delivered back | **Solved** | Both are ordinary `DELIVER`s for the trader who sent: refund as USDC or a claim, bag minted or parked. The minimum is stated in local units and scaled ×1e12, so "at least N units" on the hub is at least N here |

## 3. Implemented and proven

`anchor build`, `cargo test` and `npm run client:test` are green: **38 Rust
tests** (8 codec, 16 on the handlers, 14 against the real stack) and **57
client tests**. The real stack is the bytecode of LayerZero's mainnet
Endpoint, ULN 302, Executor, PriceFeed and five DVN programs, their mainnet
state for the Solana ↔ Base pathway, the real USDC mint, and Circle's CCTP
V2 MessageTransmitter and TokenMessengerMinter with their mainnet state,
loaded into LiteSVM (`tests/fetch-fixtures.sh mainnet`).

Wire (`src/msg_codec.rs`, `app/src/wire.ts`): ops 1–7 out, 10–13 in, the
envelope, and the option bytes. The shapes v7.2 left alone are held to the
vectors ethers generated (`tests/codec-vectors.json`: 23 op vectors, 4
option vectors); the ones it changed or added — BUY and SELL with their
minimum, OPEN, MOVE, the four-field envelope — to `tests/codec-vectors-v72.json`,
**written by hand** from the Solidity tuples (6 ops, 4 envelopes; checked
once against ethers' AbiCoder) until `gen-codec-vectors.js` is re-run on
the final contracts. The file's pre-v7.2 BUY / SELL / envelope vectors are
asserted REFUSED.

v7.2, against the real programs (`tests/test_live_endpoint.rs`,
`app/test/*.test.ts`):

- **every send names its reply budget in the envelope** — the same number
  as in the executor option — and every trade its minimum;
- **`open_token`**: OP_OPEN through the real endpoint, `open_legs` prepaid,
  the replica's rent left at its two addresses; the hub's SYNC then lands
  through LayerZero's real executor with a DRY tank and costs it nothing;
  two opens in flight; refused when the replica exists, for a wide id,
  when paused; a bag parked behind a missing replica is claimed after;
- **`move_claim`**: OP_MOVE through the real endpoint at the destination's
  price, never below a trade's legs; refused for this chain, the hub's
  label, a zero recipient, an unpriced or closed route, more than the
  claim, someone else's claim; passes when paused; comes home as a PAYOUT;
  refused whole above LayerZero's 0.05 ETH cap;
- **a moved claim arriving** for a recipient the chain never saw — a fresh
  key, another program's address, the all-zero and all-ones keys, the
  store, the vault, the tank, the USDC mint, a sysvar, this program, the
  executor itself: delivered by LayerZero's real executor with zero value;
  with a dry tank refused by the executor and delivered once the account is
  opened, the tank refilled, or the rent brought;
- **`rebalance`** through Circle's real CCTP V2 programs: the USDC is
  burned, Circle's message names the peer vault, Solana (5) → Base (6);
  not the operator, no peer, a wrong domain, a program that is not
  Circle's: refused;
- **the wiring** pins both libraries on the real endpoint, freezes the
  table, sets every route and peer, and a re-run sends nothing.

Against the real LayerZero programs (`tests/test_live_endpoint.rs`):

- registration with the real endpoint; a new admin becomes the delegate;
- **users pay**: `spawn_token`, `buy_token`, `sell_token`, `claim_fees`,
  `pull_fees` each send through endpoint → ULN → executor → price feed → DVNs,
  the user's own lamports pay the fee, the packet carries our bytes and the
  reply budget; a ceiling below the fee is refused by the ULN; a sponsored
  store (testnets) refunds from the tank and stops when it is empty;
- **entry checks** refuse before any money moves: fee mode > 3, name > 64
  bytes, symbol > 16, zero amounts, an unknown token, a deposit over the cap,
  a paused store (sells, claims and pulls still pass), a fee payer that is
  not the user. The 1024-byte metadata limit is in the program but cannot be
  reached: a spawn must fit one 1232-byte transaction, which leaves roughly
  700 bytes for the metadata URI;
- **the real executor delivers every hub message with zero value**: `execute`
  → our `lz_receive` → the real `clear`, with the account lists our
  `lz_receive_types_v2` returns (a pure function of the message: it reads
  no account, so nothing about a recipient can change or break it); replay
  fails; out-of-order nonces work; a dry-tank `SYNC` is refused by the
  executor and executed by a volunteer;
- a send fits one v0 transaction with a lookup table;
- **our verifier set** — LayerZero Labs + Google required, 1 of Horizen /
  Twinstake — set by the delegate on the real endpoint and ULN, and a buy
  sent over it (2.7× cheaper than the default set);
- every hub message fits one executor transaction.

On the handlers (`tests/test_gateway.rs`): `SYNC` from the tank, duplicate
ignored, pre-funded addresses do not block it; `DELIVER` exact to the wei
with the carry, with a USDC refund; `DELIVER` before `SYNC`, or to a missing
or frozen token account, parked then claimed; parking full is a retryable
failure; `PAYOUT` in USDC, or a claim when the vault is short or frozen or
the recipient's account is unusable, then `redeem_claim`; a `PAYOUT` for
thirteen kinds of recipient that are not a user of this chain; a value
named by the envelope taken into the tank; the fee pool
(waiting below the floor, pro rata, late stakers earn only from when they
stake, unstake, claim paid as a claim when the vault is short); `FEE_DROP`
for an unknown token fails and stays retryable; only the pad through the
adapter is heard (wrong peer, forged envelope, wrong target, wrong
recipient, a spoke op, garbage); the three roles and the pause; the vault is
named once and only over a 6-decimal mint.

**What no local test proves:** DVNs actually signing, LayerZero's off-chain
executor resolving our accounts and landing the transaction, and anything on
the Base side of the pathway.

## 4. Designed, not built

- **Token metadata.** Replicas have no Metaplex metadata account, so wallets
  show an unnamed token. The name and symbol are stored in the replica entry
  (the hub's SYNC carries them; it does not carry the metadata URI, which
  stays on the hub). A permissionless `init_metadata` paid by whoever calls
  it is the plan, its URI derived from the hub token id and served by the
  site.
- **A timelock on the admin.** The EVM side waits 48h in public before any
  topology change; this program has no delay of its own. The admin and the
  program's upgrade authority should be a Squads multisig with a time lock.
  Since v7.2 the admin also names CCTP peers — a way out of the vault.
- **Buying with a claim, selling straight from a stake.** Today: redeem, then
  buy; unstake, then sell.
- **A relayer for CCTP.** `rebalance` burns; someone must take Circle's
  attestation to the destination chain (`destinationCaller` is nobody: anyone
  can). Manual on the EVM side too. Circle's message account (428 bytes,
  0.0028 SOL, paid by the operator) can be reclaimed by its payer after
  Circle's window — no code here does it.
- **Executor gas per kind of message.** The EVM adapters got `gasForOp` in
  v7.2; this program still buys one `gas_to_hub` for every message it sends
  (a trade pays for a spawn's gas on Base: ~0.00003 ETH). A setter per op is
  an upgrade away, and nothing on the hub depends on it.
- **In the site.** Nothing yet. `app/` is the client; `scripts/cli.ts` drives
  it for the rehearsal.

Built since the last revision of this file: the outbound CCTP leg
(`set_cctp_peer`, `rebalance`); `open_token`, `move_claim`; the client and
the wiring (`app/`, `scripts/wire.ts`), the rehearsal command line
(`scripts/cli.ts`).

## 8. What stands between this program and real money

In order:

1. **A live rehearsal.** Nothing here has met a real DVN or LayerZero's real
   off-chain executor. Devnet ↔ Base Sepolia proves the pathway, the account
   resolution, the 300–480-byte deliveries and the 400k CU figure.
2. **Client code** to build the transactions (lookup table, send list, quote)
   — the rehearsal needs it, the site needs it.
3. **The hub batch, with the executor config in it** (§2 row 5). Getting the
   order wrong stops every launch on every chain for 48h.
4. **A keeper for the tank** — or the hub-side change of §9. Its balance is
   an ops alert: empty, new tokens and first-time recipients of a moved
   claim wait.
5. **Custody**: who holds the upgrade authority and the admin. With a hot key
   on either, that key can take the vault (the admin, since v7.2, also by
   naming a CCTP peer).
6. **An independent review.** ~3,200 lines of Rust hold a USDC vault and
   have been read only by their authors. The EVM side launched unaudited as
   a decision; this deserves the same explicit decision, not a default.
7. **Disclosures on the site**: stake to earn, the second transaction after a
   dev buy, a token not being on Solana until it is opened (and what that
   costs), a minimum on every trade, metadata, and — for a move TO Solana —
   that the recipient is a WALLET address (a Solana key), never an EVM
   address or a token account: the claim would be booked for a key nobody
   holds.

## 9. What Solana would still want from the hub (decide before it is frozen)

Nothing in v7.2 blocks this chain from joining: no user value can be lost
or stranded by anything the hub does or omits. Two things would make it
better and can never be added afterwards.

**1. Let the messages the pad is free to skip carry native value.** On
Solana the only hub messages that may have to create an account are
exactly those: a SYNC (the fan-out's, an open's, a `resync`'s) and the
PAYOUT a move forwards. They arrive with zero lamports because the pad
passes `returnLegs = 0` on every send. So their rent — 0.00274 SOL per
replica, 0.0019 SOL per first-time recipient — falls on this program's
tank, which nobody funds: the launcher and the mover prepaid the HUB tank,
in ETH, and that ETH can only leave through the timelocked `recover`. Anyone
can spend the Solana tank from any chain (a launch, a one-micro-dollar move
to a fresh address), at a cost to themselves of the same order; when it is
empty those two kinds of message wait (LayerZero's executor declines; the
packet stays executable). Nothing is lost, trade replies are untouched —
but it is an unfunded subsidy with a liveness edge.

The change is four call sites in `SpawnPad` — `_trySend`, `_within`, and
`resync`'s quote and send pass `1` leg instead of `0` — and no new storage:
the hub adapter then attaches `returnUnit[dst]`, which on the HUB adapter is
dead configuration for every remote label today (`setDestination(label,
gas, 0)`: 0 for every EVM chain, so nothing changes for them), and would be
set to the rent for label 1 (≈ 3,000,000 lamports; LayerZero's cap toward
Solana is 0.24 SOL). The envelope already carries the number. This program
is ready for it either way: a value the envelope names is taken from the
delivery into the tank (`lz_receive.rs`, tested through the real executor),
so the message funds what it creates and the tank ends where it started.
If the hub does this, `open_token` should stop leaving the rent itself.

**2. Send home a move whose recipient is shaped like an EVM address when
the destination is not an EVM chain.** `_move` refuses a wide `to` for an
EVM gateway; the mirror is missing: for a wide gateway any non-zero `to` is
forwarded, including a left-padded 20-byte address — the likeliest mistake
of a user moving a claim to Solana from an EVM wallet. Here it can only
become a claim for a key nobody holds. `wide(gw) == wide(to)` in place of
`wide(gw) || !wide(to)` sends it back to its owner instead. A Solana key
with twelve leading zero bytes does not occur, the same fact `_move` already
relies on.
