# Solana leg — notes

**Where it stands (2026-11-14).** The program speaks **protocol v7.2** — the
wire of the hub that is about to be deployed — and is mainnet-shaped: real
USDC settlement, users paying for their messages and the replies, a minimum
on every trade, opening a token and moving a claim, CCTP out, roles and
pause. It is proven locally against the real **mainnet** LayerZero programs
and state and Circle's real CCTP V2 programs. It has **never been deployed,
not even to devnet**, and is not audited.

The design, every constraint the immutable hub puts on Solana, the
measurements, the deployment plan, the hub-side timelock calls and **what
Solana would still want from the hub before it is frozen (§9)** are in
**[V7.md](V7.md)**. This file is the working memory: how to build, what the
pieces are, the facts and the traps.

## Build and test

```bash
cd solana
./tests/fetch-fixtures.sh mainnet   # once per clone: ~7 MB, gitignored, read-only RPC (LayerZero + CCTP)
anchor build                        # must precede cargo test (tests load target/deploy/*.so)
cargo test                          # 38 tests
cargo test -- --nocapture           # with the CU, fee, size and rent numbers
npm run client:typecheck && npm run client:test    # 57 tests
```

`anchor build` also builds the IDL, which compiles the TEST targets: a test
that does not compile fails the build ("Building IDL failed") after the
`.so` is already written. `cargo build-sbf` alone rebuilds the program in
ten seconds. The linker's "Stack offset … exceeded" lines name functions of
a dependency (`crypto_common`) that the program never calls.

**The vectors.** `tests/codec-vectors.json` (29 op vectors, 3 envelopes, 4
option vectors) was generated by `contracts/scripts/gen-codec-vectors.js`
BEFORE v7.2: its BUY / SELL (three words) and its envelopes (three fields)
are the old shapes — the tests assert they are refused and hold everything
else to it. The v7.2 shapes are in `tests/codec-vectors-v72.json`, **written
by hand** word by word. Once the contracts are final: re-run the generator,
point both codec tests at the new file, delete the hand-written one.

Nothing in the tests touches a wallet or a cluster: the fixtures are
account reads and `solana program dump`.

- **The executor** (read from its source): `execute` requires the caller's
  balance not to drop by more than the option's `value`. The option's `gas`
  is the compute budget. A failed delivery aborts the transaction and leaves
  the packet verified: anyone may execute it later. Its config caps the
  value ONE message may carry: **0.05 ETH toward Base**, 0.24 toward
  Ethereum / Arbitrum / Optimism, 1.32 toward BNB (mainnet snapshot) —
  above it the quote, hence the send, fails `NativeAmountExceedsCap`.
- **The endpoint's libraries**: an OApp's `SendLibraryConfig` /
  `ReceiveLibraryConfig` hold the all-zero key until it pins one
  (`set_send_library` / `set_receive_library`, delegate only): zero means
  "whatever the endpoint's default is, now and later". The wiring pins both.
- **Lookup tables** have no "set authority": the creator keeps it (extend,
  deactivate, close) or freezes the table for good.
- **Circle CCTP V2** (source: `circlefin/solana-cctp-contracts`, and the
  mainnet programs run locally): MessageTransmitterV2
  `CCTPV2Sm4AdWt5296sk4P66VBZ7bEhcARwFaaS9YPbeC`, TokenMessengerMinterV2
  `CCTPV2vPZJS2u2BBsUoscuikbYjnpFmbFsvVuJdgUMQe`; Solana is domain 5.
  `deposit_for_burn` burns straight from the owner's token account (the
  owner signs: the store PDA), needs a fresh signer account for its message
  (428 bytes, paid by `event_rent_payer`), refuses an owner on Circle's
  denylist, a `max_fee` under its minimum fee (0 on mainnet today — ours is
  0, like `OmniUSD.rebalance`) and more than 10,000,000 USDC per message.
  The remote TokenMessenger of Ethereum, Optimism, Arbitrum and Base is
  `0x28b5a0e9C621a5BadaA536219b3a228C8168cf5d`.
- **Rent** is (128 + bytes) × 5,080 lamports on mainnet AND devnet today.
- **`clear`** burns the packet (replay protection) and must run before any
  state change. Its eight accounts come first in `lz_receive`'s remaining
  accounts.
- **Sends**: the ULN charges the actual fee and requires only that it stays
  within the `native_fee` it is handed — no on-chain quote is needed.
- **Model**: an OApp is a Store PDA registered with the endpoint, a delegate
  for its config, a Peer PDA per remote eid, and `lz_receive_types_v2` so
  the executor can learn the accounts (Solana has no dynamic account
  access). [Solana OApp reference](https://docs.layerzero.network/v2/developers/solana/oapp/overview).

## Traps, each one paid for

- **No try/catch.** A CPI that fails takes the hub message down with it.
  Check first, then transfer; what cannot be settled becomes a claim or is
  parked.
- **Heap.** A quote CPI followed by a send CPI over a mainnet pathway (one
  executor + four DVNs) runs out of the 32 KB heap ("memory allocation
  failed"). The send passes the caller's ceiling instead.
- **The endpoint refuses writable accounts on a quote** while a send needs
  them writable: `quote_send` passes read-only clones.
- **Transaction size.** A send is 33–40 accounts, up to 1509 bytes as a
  legacy transaction. Clients need v0 and a lookup table.
- **Rent differs.** Mainnet charges (128 + bytes) × 5,080 lamports today
  (`solana rent -u mainnet-beta`); LiteSVM and a local validator charge the
  old 6,960. Never hard-code a rent figure.
- **`lz_receive_types_v2` must unwrap the envelope** before reading the op —
  the pre-v7 version read the op from the raw message.
- **Fixtures are a snapshot.** The fees and verifier lists the tests print
  are those of the day `fetch-fixtures.sh` ran.
- **An address that holds lamports is not an account of ours.**
  `open_token` leaves rent at the replica's and the mint's addresses; anyone
  can pre-fund any address. Check the owner and the data before decoding
  (the client's `own()`; the program's `load_replica` / `locate_user`).
- **A tank drained to zero cannot take less than its rent floor** (650,240
  lamports): the runtime fails the transaction. `lz_receive` skips the
  value sweep in that case; `recover_tank` should leave the floor.
- **A new send needs its arm in `quote_send`** (it knows ops 1–7), its
  entry in the client's `SENDS`, and — if it creates accounts on arrival —
  nothing in `lz_receive_types_v2` may depend on chain state.
- **Never fail a hub message for what an account IS.** The executor's list
  is fixed by the message; the handler decides. A `require!` on something a
  user on another chain can choose strands their value.

## Client (`app/`) and wiring (`scripts/wire.ts`)

```bash
npm run client:typecheck     # core with no Node types (browser-safe), tests, scripts
npm run client:test          # LiteSVM (npm litesvm 0.3.3) + the mainnet fixtures
npm run wire -- --cluster devnet --dry-run --admin <key> --hub-eid 40245 \
  --hub-pad 0x… --hub-adapter 0x… --verifiers default --spawn-legs 3
```

```bash
npm run cli -- status --cluster devnet                 # reads; dry run by default for everything else
npm run cli -- buy --token 0x… --usdc 5 --min-tokens any --keypair <file> [--send]
```

`scripts/cli.ts` is the rehearsal's command line: status, balances,
pending, quote; spawn, buy, sell, claim-fees, pull-fees, open, move; redeem,
claim-parked, open-account. It prints what it would send (fee, reply
budget, the message bytes, the simulation) and sends only with `--send`.

`app/src/client.ts` (`GatewayClient.load(connectionRpc(conn))`) reads the
store, the peer, the effective LayerZero send path (OApp config merged over
the pathway default, each worker's price feed read from its config) and the
table the store names; it quotes by simulating `quote_send` and builds
unsigned v0 transactions (700k CU for sends). Sends are entries in
`SENDS` (`app/src/instructions.ts`): each says its accounts, its arguments,
its legs and — for a move — the route account that prices it. The tests check builders and decoders
against the IDL through Anchor's coder, the codec against
`tests/codec-vectors.json`, and run every user instruction and the whole
wiring through the real LayerZero programs. Devnet's default pathway
toward Base Sepolia is one required DVN (LayerZero Labs, the same config
account as mainnet), 10 confirmations; the devnet RPC faucet is closed
(faucet.solana.com instead).

## History

- **Phase 1** — toolchain and a deployable skeleton.
- **Phase 2a** — the OApp skeleton, the byte-exact codec, the receive path
  with a stand-in dollar mint.
- **Phase 2b-local** — the send path against the devnet LayerZero stack
  loaded locally; the protocol tank paid for every message.
- **Protocol v4 / v5** (EVM side) — every account on the wire became
  `bytes32`; the inter-adapter envelope; the hub stores actors as `bytes32`.
- **v7 port** — USDC vault and claims instead of the stand-in
  mint, users pay, op 5, parking, the stake-to-earn pool, roles and pause,
  the mainnet fixtures. Removed: `init_usd_mint`, the enforced options in the
  Peer PDA (the program builds its options from `set_fee_config`), the
  on-chain quote before each send.
- **v7.2 port (this state)** — the minimum on trades, the envelope's value,
  `open_token`, `move_claim`, a PAYOUT for any recipient, `set_receive_table`,
  a store born paused, the libraries pinned and the table frozen by the
  wiring, CCTP out, the rehearsal command line.
